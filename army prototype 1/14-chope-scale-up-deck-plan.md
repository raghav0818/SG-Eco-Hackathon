## The claim to earn

> **Chope links an anonymous meal-intent count, the kitchen's actual cook count, and portions left after service in one visible feedback loop. It gives cooks a bounded number before the meal and uses the two after-service counts to update the next forecast.**

The poll is the input, not the main invention. The feedback loop is the product. The proposed first buyer is a catering contractor; kitchen staff and the unit food IC are the working users, and servicemen only answer an anonymous poll. Contractor willingness to buy is **unverified**. The camp setting is the intended beachhead, not a site where this prototype has operated.

**Critical correction:** The current bot's `/saved` message says “portions NOT cooked” and then implies the special lunch is paid for. In the slides call this a **counterfactual count versus the all-silent-eat rule in a demo**, never kilograms diverted or cash saved. The code receives Telegram command messages containing sender metadata transiently even though *poll responses* are anonymous; say “no individual poll votes are stored,” not “the bot never sees any user ID.”

**Another script correction before filming:** The current bot says “plates came back,” “eaten,” and compares leftovers with yesterday. Its two keypad inputs record **portions cooked** and **portions left unserved**, not plate returns or food actually consumed. Rewrite or visibly annotate those messages before using a screenshot. A previous day's leftover count is also not a matched comparison: menu and headcount may differ. The “food you didn't waste pays for lunch” line is a prize hypothesis, not an observed financial result.

## The one test that most improves this deck before 1 October

Run the whole showcase path on the **actual Pi, screen and USB keypad**: `/demo` on one phone → real Telegram vote → poll lock → `COOK` screen → key **actual cooked** and **left unserved** → aggregate scorecard → changed next-state/CSV. This remains **pending**: the project decisions list the Pi keypad, sticker packs, demo group and venue connection as open checks. Photograph the setup and record one continuous screen-and-hands video. Keep a log with date, location, who tested, whether it completed without intervention, observed delay, and every failure. Reset and run at least once again after a Pi reboot; the second run checks the state path. The 71 votes and leaderboard rivals must be **visibly labelled “seeded demo”** in the presentation. A visitor's one genuine vote proves interface interaction, not 90 real votes or retention. If the live chain fails, show the recorded real hardware run only if one succeeded; otherwise use honestly labelled code/screenshots and explain the failure.

If a kitchen worker or caterer can be reached remotely, show the actual board/keypad flow and ask: “Would entering actual cooked and leftovers fit service close? Who can change the cook number?” Record their answer and whether they saw a simulated meal. **Do not convert a casual visitor comment into a cookhouse validation claim.** The [current decisions](13-chope-fun-bot-decisions.md) say no real Telegram trial; revise that label only after a trial is genuinely run.

## Impact and budget slides: only numbers with provenance

`measured avoided kg/site-day = baseline discarded kg on comparable meals − intervention discarded kg on comparable meals`, reported with menu, headcount, service length, actual cooked, stock-outs and where leftovers went. An optional expansion scenario is `eligible sites × meals/site/year × measured avoided kg/meal × adoption factor`; leave it symbolic until the pilot yields a credible per-meal estimate and a bounded number of eligible sites. **Fewer forecast portions are not automatically food that would otherwise have been cooked or binned.** The current attributable avoided kg is **unmeasured**.

Budget a **six-month, one-site pilot plus a possible two-site extension**, not a national rollout. Put quantity, unit cost, source/date, and total on every line; separate cash expense from donated/owned gear and staff time.
